## حدود الاختبار والنشر

لم تُشغّل اختبارات التطبيق أو بناؤه ضمن هذه التهيئة؛ نتائج ذاكرة المطور لا تثبت سلامة المنتج أو جاهزية إطلاقه.

[طلب المراجعة](https://github.com/ibraabyte/Cockpit/pull/1) مسودة على `chore/project-brain` مقابل `main`. يحوي ملفات الذاكرة وتعليمات الجلسة وفهرس الوثائق اللازم فقط. لم يُدمج تلقائيًا ولم يُنشر تاريخ عمل المستخدم الآخر. فُحص الفرع وHEAD وبايتات التجهيز قبل وبعد عملياتنا، دون تبديل الفرع أو إعادته إلى لقطة قديمة.

يحفظ كل جهاز فهرسه وقاعدة مهامه خارج كل مجلدات Syncthing. بقي اتجاه Projects كما هو: الماك بوك إلى الميني. لا تعمل بكاتبين متزامنين على المصدر أو الذاكرة. لا تفهرس تسليمات قديمة خامًا أو أسرارًا أو ملفات بيئة.

## الاستمرار

ابدأ بالعربي، وافحص Git الفعلي واقرأ [نقطة التوقف](../current-state.md) والقرارات. شغّل `context-pull` و`tasks-pull`. إذا كانت لديك ملاحظة محلية غير منشورة أو تعارض، احفظها وراجعها قبل الجلب؛ لا تستخدم force أو reset. في النهاية حدّث checkpoint والتسليم، وسجّل سبب القرار المهم واختباراتك، وانشر Markdown المراجع ثم تاريخ المهام منفصلًا كما في [الاستخدام اليومي](../daily-use.md).
